Migrate a legacy desktop GIS project (QGIS projects and models, ArcPy/PyQGIS scripts, notebooks, Excel, hand edits) into a reproducible Python codebase and a cloud job, verified step by step against the legacy outputs, with a status computed by ladder.py (discover → interview → plan → build step by step → verify → report → Databricks bundle, never deployed). Use when the user runs /axis-migrate:migrate <folder> or asks to migrate, port or verify a legacy GIS folder, or to resume one that has a migration/ folder.
- axis-migrate:start: Codex entry point for axis-migrate (what /axis-migrate:migrate is under Claude Code). Compare every lineage pair (compare.py), render legacy | new | difference plots (plot.py), LOOK at every compared dataset — on the GeoLibre map views (map skill) where the harness has a browser pane, else at the PNG plots — and answer the calibrated rubric (review-add; you may only flag), aggregate verdicts and blame, run the repair loop within its limits, and propose (never sign) tolerance records. Use after every isolated step run while migrating and after the chained run.
- dataviz: Use before creating any chart, plot, map visualisation or dashboard, in any library.
- axis-migrate:report: Seal a verified run into a hash-checked evidence bundle, compute the status rung with ladder.py and render migration/report/index.html (failures first, swipe map, per-dataset map views and receipts, parity table, run history). Use after compare, plot, visual review and aggregate have finished on a CHAINED run, after target_check.py (to seal target evidence), and whenever you need the current status line.
- axis-migrate:interview: Investigate every output-changing parameter of a legacy GIS workflow from its files (params.yaml with file:line citations), then ask the analyst only what the files cannot answer and parity cannot catch, one question at a time, and record answers in decisions.md. Use after discover has written graph.json and before planning code.
- code-review: Review the current diff or a pull request for correctness bugs.
- xlsx: Use when a spreadsheet file (.xlsx, .csv) is the primary input or output: open, edit, clean or create one.
- axis-migrate:map: Look at legacy vs new results on a live map (GeoLibre, local only) and show them to the person in the harness's own browser pane. Build the views of a compared run (legacy, new, diff and validity COGs, GeoJSON, one GeoLibre project per view), start the local map server, open the views, switch the raster engine, toggle layers and identify cells. Display only; use after compare.py (and plot.py) on a run.
